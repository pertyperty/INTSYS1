# Laravel-FastAPI contract (v1)

The Python service implements the [OpenAPI definition](openapi.v1.yaml) for liveness, protected chat, and read-only source and barangay catalogs. FastAPI provides `/openapi.json` on loopback and tests compare routes, fields and security with the checked-in contract. Laravel throttles browser requests and reports upstream failures without exposing internal details.

- The browser calls Laravel for SANDIG API data. FastAPI binds to loopback for native development; no public CORS or Ollama exposure. FastAPI chat and both catalogs require a server-only bearer token. Laravel enforces session, CSRF, and user-facing throttling. Health is liveness only.
- Chat is synchronous. `conversation_id` is optional correlation, not backend storage or memory. Send a listed `barangay_id` or `null`; the browser now omits it. An unknown ID returns a generic 422 when the catalog is available, except emergency messages are handled first. The roster can flag name mentions as possibly local, not determine a location or conditions. Never send coordinates in chat. `language: auto` uses English/Filipino cues from the current message; ambiguous input falls back to English. Explicit `en` and `fil` still work; omission still means `en`.
- `auto_web_search` and `allow_web_search` are strict booleans defaulting to `false`. Laravel enables automatic fallback by default. `allow_web_search` is only for an affirmative request; disable both fields for web-off mode. `web_search_used` means general search was attempted, not that it found evidence. Official live lookups are separate. `checked_at` records successful external verification, not message creation.
- Render answers and passages as plain text. Display citation kind, publisher and available dates. Use validated HTTPS links only. Indexed catalog citations include `source_id` and `version`; static emergency references use the same v1 shape with both fields null and are labeled separately. `curated_guidance` is bundled general guidance, not indexed evidence or a live or web result. Sources lists active approved metadata only.
- Insufficient evidence, refusal and emergency are valid outcomes (`200`). Emergency handling precedes retrieval and external calls. Failed live verification must not imply no warning or substitute historical data. Use `503` when no safe result can be produced. Do not echo invalid request content or expose raw internal errors.
- With both model flags enabled, a general preparedness reply without matching approved or curated material can be `response_type: preparedness` and `evidence_status: insufficient_evidence`. It is provisional even if `web_search` links are attached; those links are not citations supporting the generated claims. Web-off mode does not disable local generation.

Chat can also return `not_applicable` for greetings, thanks, and test messages that make no evidence claims. `supported` and `official_live` remain reserved. Brief, standard and detailed return up to two, three and five semantic matches, or one, two and three lexical matches if semantic retrieval yields none. With `SANDIG_ENABLE_RAG_CHAT`, eligible preparedness answers can be generated locally from retrieved evidence without changing the request or response schema; citations are not proof that every generated claim is correct. Current warnings and local hazard claims still abstain with agency pointers where applicable; those pointers are not verified bulletins.

- `Recent USGS earthquake reports` requests a supplementary live lookup when enabled. This never calls general search. `checked_at` is when a fresh feed snapshot was validated (retained on cached responses), even if no regional reports match. `observed_at` is event time; a failed check returns neither citations nor `checked_at`.
- `Is there a storm happening here?` and `May bagyo ba dito ngayon?` request a model-based Open-Meteo estimate for a fixed Baguio City point when enabled. The browser does not send GPS coordinates. `observed_at` is the estimate's valid time, not a station observation; `checked_at` is the successful feed check. This is separate from Brave and does not verify PAGASA warnings.
- The response `language` is `en` or `fil`. The browser uses it for the answer text so assistive technology can select the right pronunciation.
- `auto_web_search: true` permits link-only search on general preparedness if neither approved excerpts nor bundled guidance matches. Catalog outages do not trigger automatic search. Explicit `allow_web_search: true` permits further reading even when guidance is available. Neither path applies to emergencies, current or local conditions, or unrelated requests. Both return at most four unverified links from approved publisher domains, prioritizing Philippine sources. Links never increase evidence status or set `checked_at`. A disabled or throttled search returns `web_search_used: false`; an attempted but failed call returns `true`.

`GET /api/v1/locations/barangays` returns `{barangays: [{id, name}], source: {publisher, url, as_of}}`. IDs are strings; `as_of` is the source's roster date (ISO calendar date), not a hazard observation date. The catalog sorts by name and loads locally without PostgreSQL or an internet connection. Missing or invalid snapshot data returns 503 at this endpoint only. No geometry or hazard claims are returned; selection does not change national preparedness retrieval.

`sources` uses stable source-ID order and opaque signed continuation cursors; invalid cursors return 422, and key rotation invalidates old cursors. A missing database URL returns an empty catalog; a configured but unavailable or uninitialized database returns 503. Write operations and operator semantic diagnostics use the [CLI](guides/02-document-ingestion.md). The chat response still has no geographic evidence fields; see the [architecture](architecture.md) for future compatibility.
