# Architecture decisions

- **Chat overhaul: separate history, location and fallback.** Persist recent turns only in the Laravel session, which avoids accounts and cross-device storage for the prototype. Do not forward chat history or browser GPS to FastAPI. Infer reply language with a small deterministic cue set rather than depend on model availability or send personal content to another provider. Default automatic web fallback on in the browser, but constrain requests to preset searches for general preparedness without eligible indexed evidence. Keep curated guidance, search links and current reports distinctly labeled.

- **Phase 5: keep external results separate by purpose.** Prefer a documented, bounded supplementary feed to fragile scraping of authoritative bulletin pages. Link Philippine agencies without claiming their current status. General web search is an explicit, link-only operation behind the evidence boundary; unverified results never alter evidence strength. Use process-local throttles for this workstation; require budget and egress controls before distributed deployment.

- **Phase 3: separate evidence from answer generation.** Use a bounded PostgreSQL lookup for approved public excerpts and keep embedded Chroma private to the operator CLI. This avoids concurrent Chroma ownership and browser-time inference; lexical overlap can miss paraphrases and cannot prove factuality. The public response labels excerpts partial. A later generation gate must check claims against typed evidence, not compare model confidence.
- **Future GIS: spatial adapter, not document extraction.** Use a separate typed API projection rather than forcing map product metadata into plain text citations. The Phase 4 PSGC roster contains only place identifiers, runs offline, and does not require coordinates. Keep boundary and map editions separate from roster updates. No spatial lookup endpoint, GIS dependency or hazard dataset was added.
- **PostgreSQL is authoritative for source state.** Chroma stores vectors and generation identifiers, not publishable metadata. Compared with relying on Chroma metadata alone, this lets deactivation and approval switching take effect even when vector cleanup is unavailable.
- **Use a local operator CLI before browser admin.** This proves lifecycle behavior without putting file uploads or write operations behind a public web route. It assumes a trusted workstation operator; browser authentication and a formal approval workflow are separate work.
- **Do not generate public answers in Phase 2.** An overlap threshold and vector score do not establish an answer's factuality or safety. The diagnostic returns candidate excerpts so operators can assess retrieval before adding claim verification, domain scope, and emergency priority.
- **Separate embedding generations by model digest.** Reindex instead of mixing vectors across embedder changes. The default Chroma namespace is also tied to the PostgreSQL catalog identity so one test catalog cannot make another catalog's generations eligible for retrieval or cleanup.
